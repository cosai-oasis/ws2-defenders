# Telemetry for AI Security

> **Version 0.6 — Request for Comments**
> CoSAI Workstream 2 (Defenders). This is a proposal for discussion and feedback, not a final standard.

This folder specifies the security telemetry an AI system needs to produce: which fields to emit, the documented attacks that make each one necessary, the detections the fields enable, and how they map onto OCSF, OpenTelemetry and other standards. It also holds the data and tools the documents are built from, and AITF, a framework that emits to OpenTelemetry and OCSF today.

At v0.6 the catalog has 102 fields (53 MUST, 33 SHOULD, 16 MAY), grounded in 61 documented attacks and incidents and combined into 53 correlation patterns.

## Where to start

- **CISOs:** [RFC §3.1](CoSAI-AI-Telemetry-RFC.md#31-for-cisos), then the field catalog in [RFC §6](CoSAI-AI-Telemetry-RFC.md#6-field-catalog). The MUST fields that apply to a deployment are its baseline.
- **Defenders setting up collection:** the seven steps in [RFC §3.2](CoSAI-AI-Telemetry-RFC.md#32-for-defenders-of-ai-systems).
- **Standards and SDK maintainers:** the [Cross-Mapping Addendum](Telemetry-Cross-Mapping-Addendum.md), starting with the asks of OCSF ([XM §1.4](Telemetry-Cross-Mapping-Addendum.md#14-asks)) and OpenTelemetry ([XM §2.4](Telemetry-Cross-Mapping-Addendum.md#24-asks)).
- **Contributors changing a field, attack or pattern:** [build-telemetry/README.md](build-telemetry/README.md).

## Changing the documents

Much of the three documents is generated from `build-telemetry/data/`: the RFC §6 field tables and tier totals, the AD field entries, patterns and inventory tables, and the XM pins, correspondence tables and asks. Some of these regions sit between `<!-- BEGIN GENERATED -->` and `<!-- END GENERATED -->` markers, and some (the RFC §6 tables, for example) have no markers. Edit the data, not the generated text. `tools/build.py --check` reports any document that no longer matches the data.

```
cd telemetry/build-telemetry
pip install pyyaml
python3 tools/validate.py   # first run fetches the pinned sources into ~/.cache/cosai-telemetry/
python3 tools/build.py      # regenerates the documents and the explorer
python3 tools/validate.py
```

A change of judgment, such as a new attack-to-field edge, a tier basis or a pattern, goes through the candidate registry in `data/candidates/`. See [Changing the data](build-telemetry/README.md#changing-the-data).

## AITF

[aitf/](aitf/) is the AI Telemetry Framework. David Girard proposed it, and it is now donated to and maintained by CoSAI. It extends the OpenTelemetry GenAI semantic conventions, maps to OCSF, and ships SDKs in Python, TypeScript, Go and Rust, along with a collector configuration, vendor integrations and examples. It has its own version (v0.4) and is licensed under Apache 2.0 ([aitf/LICENSE.md](aitf/LICENSE.md)). [XM §3](Telemetry-Cross-Mapping-Addendum.md#3-aitf) maps the field catalog onto it.

The planning notes at the top of `aitf/` (`upstream-status.md`, `AITF_gaps.md`, `upstream-pr-plan-*.md`) were written against RFC v0.4 and cite its appendices, which v0.6 replaced with the two addenda. For the current mapping and asks, use XM.
